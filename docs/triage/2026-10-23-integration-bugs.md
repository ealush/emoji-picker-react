# Integration bug audit: 5.1.0

Audited against `master` commit `183d24c` (package version 5.1.0). The supplied 49-app/56-pin census and consumer timings are external estimates, not independently verified here. Patch priority scores below are maintainer judgments, not CVSS: 8–10 release blockers, 6–7 next-patch work, 3–5 ordinary fixes. A dash means no verified production bug to score.

## Verdicts

| # | Claim | Patch priority / 10 | Verdict and evidence |
| --- | --- | --- | --- |
| 1 | Per-emoji timer storm | 9 | **Confirmed and fixed for image styles.** Native, the default style, returns before the preload path. A Chromium fixture using Apple images and typing `rocket` scheduled 7,086 preload timers on original master and zero with this patch. A deterministic unit repro scheduled 8,000 timers for distant cells before the fix. Bounds checks now precede work; rendered-only preloads use the writer's cache key, and image work runs after commit rather than during render. The supplied seconds-per-word figures were not reproduced. |
| 2 | Columns picker collapses without results | 8 | **Confirmed and fixed.** Original Chromium repro lost 125.03 px of width on a no-match query. A permanent, zero-height intrinsic sizing row preserves the grid's width during empty, loading and error states. Existing narrow-container, tone-fan and preview-width checks still pass. |
| 3 | Consumed Escape reaches host dismissal | 7 | **Confirmed and fixed.** Search-clear and highlight-clear paths did not stop propagation. They now consume Escape in window capture, ahead of document-capture dismissal (including Radix) and bubbling host handlers. Subsequent Escape with nothing to undo is untouched. Browser expectations now explicitly cover menu → search → host dismissal. |
| 4 | Slow first open and section pop-in | 6 | **Avoidable work confirmed; optimized.** Unmeasured categories could construct their entire cell inventory before geometry was available, and section heights reached the parent through passive effects. Measured layouts now wait for final offsets before constructing cells and report section heights during layout. No independent confirmation of the cited 160 ms comparison or a universal first-open speedup. |
| 5 | Every section refilters on scroll | 7 | **Redundant work confirmed; optimized.** Filter predicates and filtered inventories are memoized with data/search/tone/support/failure invalidation. Category callbacks are stable; memoized sections receive clamped scroll positions outside their render margin. A deterministic test verifies scrolling does not refilter unchanged inventories; native-support and failed-image recovery tests protect invalidation. The claimed 230–400 ms frame was not independently reproduced. |
| 6 | cssLayer causes whole-page restyle | — | **Not reproduced in the library fixture.** Chromium tracing with 1,000 unrelated spans showed the same local pattern with an undeclared layer, a predeclared layer and no layer: the largest recorded style update was 140 elements; closing updates involved one element. Styles do mount/unmount, but that alone does not establish the claimed whole-page invalidation. Keep the host trace/repro as an open investigation; no stylesheet-lifetime rewrite in this patch. Repro stories and Chromium tracing regression checks are included. |
| 7 | English data remains in default entry with emojiData | — | **True bundle property; documented entry contract.** `src/index.tsx` synchronously registers English data. Runtime props cannot tree-shake that import. The primitives entry already supports caller data without the synchronous English dependency. Making the batteries-included entry asynchronous or adding a lean assembled entry is a separate API/bundling change. The supplied 44 kB gzip figure was not separately established. |
| 8 | Weak substring search/ranking | — | **Search enhancement, not a patch regression.** The shared search core explicitly preserves dataset order and matches name substrings. Token matching, glyph lookup, canonical Slack aliases and relevance ranking need an explicit search contract and separate tests. Do not claim `parrot party` support without an alias or token-matching policy. |
| 9 | External result changes leave highlight/preview stale | 6 | **Partly confirmed and fixed.** Applied controlled search already triggered a highlight reset. Replacing or reordering caller suggestions did not. Highlight/preview synchronization now also follows suggestion and dataset changes; the regression keeps the old highlighted emoji present but changes its order, proving reset rather than merely unmount cleanup. |
| 10 | First Down does not move past the first result | — | **Current documented behavior.** Typing alone does not start a keyboard highlight. The first arrow toward the grid starts it on the first result; subsequent arrows move it. A preview/default active emoji is not already a keyboard selection. Changing this is an interaction decision, not an off-by-one fix. |
| 11 | Rapid arrows collapse into one movement | 6 | **Confirmed and fixed.** Deferred focus read the same source cell for successive keys. Mounted destinations now move synchronously. A logical pending cursor accumulates movement while unmounted destinations materialize; obsolete destinations stay generation-guarded and scrolling remains deferred/cancellable. Tests cover two same-frame horizontal presses and ten vertical presses across the virtualized window. |
| 12 | Unlayered library CSS beats layered app CSS | — | **Known cascade tradeoff, not accidental specificity.** The default remains compatible with unlayered global resets; `cssLayer` and a layer-order guide already exist. Changing the default affects existing consumers and belongs in a deliberate styling/API decision. This report does not treat every `!important` in an app as proof of a library defect. |
| 13 | Missing primitive focus-border/placeholder defaults | — | **Not reproduced with the supported token/theme setup.** Both variables are present in `lightPickerTokens` and therefore `defaultPickerTokens`. A theme-free bare Root deliberately does not install light appearance values. Provide the actual composition/token preset to establish a missing-default bug. |
| 14 | Font token set to inherit still yields library font | 4 | **Confirmed and fixed in Chromium.** The old universal descendant declaration fell back to sans-serif. Typography now resolves at the root with an inherited fallback, descendants inherit it, and the default sans-serif value is a token. Native emoji font handling remains separate. |
| 15 | Custom category header loses sticky background | 4 | **Confirmed and fixed in Chromium.** Custom headers received geometry classes but not default appearance classes. Under default appearance they now receive the same background/typography classes as built-in headers; theme-free compositions remain undecorated. |
| 16 | Custom emoji display names are lowercased | 4 | **Confirmed and fixed.** The custom-data adapter lowercased names before they reached captions, accessible labels and callbacks. It now copies names unchanged and folds case only for matching. IDs remain case-insensitive. Consumer fixtures now assert preserved `Panda` display/callback text. |
| 17 | Skin-tone swatch is always yellow / unthemeable | — | **Overstated.** The neutral swatch is hardcoded yellow, but the other five tones have their own colors and active selection changes. Existing custom `SkinToneButton` composition permits replacement. Dedicated swatch color tokens would be an additive styling feature. |
| 18 | Search/pick cannot be tested in jsdom | — | **Real platform limitation, not a universal failure.** Existing integration tests already perform search then pick in jsdom using an IntersectionObserver shim. A no-op observer can strand later categories, and virtualization requires geometry for navigation tests. An official shim/render-all testing mode is useful feature work; production rendering should not be disabled to accommodate an incomplete shim. |
| 19 | 149 FE0F identities differ from www data | — | **Not established as a library defect.** No authoritative www dataset/fixture was supplied to compare the count or consumer contract. Different valid emoji-presentation forms do not by themselves justify rewriting generated IDs. Suggested emoji glyphs already try presentation-selector variants. Unified-ID portability beyond that needs concrete failing sequences and a documented normalization policy. |
| 20 | Enter after typing picks the old grid | 8 | **Confirmed on 5.1.0 and fixed.** Accepted/displayed text changes before the debounced applied query. Selection now checks that both match the rendered query. Enter during pending filtering is consumed without selecting stale data; another Enter after results commit selects normally. This is a conservative correctness fix, not an implicit flush/queued-selection API. |

## Reproduction and validation

New unit regressions live in `test/hooks/preloadEmoji.test.ts`, `test/hooks/useEmojiVirtualization.test.tsx`, `test/keep-search-focus-v5.test.tsx` and `test/list-components-v5.test.tsx`. Existing custom-emoji, recovery and cancellation coverage remains active. Browser fixtures are in `stories/picker/Columns.stories.tsx`; browser regressions are in `playwright/adoption-behavior.spec.ts`.

The four new browser checks for timers, no-match width, inherited font and custom-header background were first run against an isolated original-master worktree with the same new fixtures. All four failed on the expected behavior. They pass against the patch. The fixture uses data-URL images, so image-CDN availability does not influence the timer repro.

The complete unit suite passes: 970 tests in 114 files. All 49 Chromium adoption-behavior checks pass. Browser verification uses Chromium; Firefox, WebKit and touch were not run here. Validation also includes lint, source/tooling/script types, build, compatibility/contracts, React 16 packed-consumer checks, and the published-entry/tarball size budgets.

**Release blockers:** the deeper packed-package check rejects the primitives initial-load fixture at approximately 34.4 KiB gzip against its unchanged 34 KiB limit. The original master fixture is approximately 33.99 KiB. This patch therefore needs a further initial-bundle reduction before merge/release; the budget has not been raised. The timing gate also requires review: a quiet rerun passed search and mount budgets but failed cold data preparation (6.798 ms vs a frozen 5.494 ms baseline, 123.7% against a 110% cap). This does not establish that the patch caused the preparation gap; the baseline was frozen with a different environment. This change is a local draft for review, not a release-ready 5.1.1.

This execution environment blocks tsx CLI Unix IPC and OS network-interface enumeration. Tests/build scripts were run with a temporary harness that invokes the same tsx loader through Node; the browser server used a loopback-only interface stub. Neither workaround changes repository tooling, dependencies or production code. Chromium was obtained from a separate temporary serverless package after the regular browser download failed.

## Release scope

Ship confirmed correctness fixes as a patch, including #20 as well as #1–3. Treat #4–5 as targeted performance improvements, with no claim that consumer-specific timings or the 49-app census were reproduced. Keep #6 open for host-specific evidence. No dependency versions, size budgets or generated emoji datasets are changed.

The separate feature list remains minor/major planning work. Compact sizing, typography/shape tokens and a separately labeled preset row are sensible next candidates, but the supplied adoption counts are estimates and do not authorize silently changing default CSS layering, search order or data-loading semantics in a patch.
